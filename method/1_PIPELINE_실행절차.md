# L1 · PIPELINE — 실행 절차

> **이 문서의 지위**: L0(철학·판단 기준)을 실제 작업 순서로 번역한 것. 프로젝트를 시작할 때 이 문서를 열고, 단계마다 산출물을 남기고, 게이트를 통과시킨다.
>
> **읽는 방법**: 각 단계는 `입력 → 작업 → 수행 → QnA → 산출물 → 게이트` 여섯 칸으로 되어 있다. 산출물이 없으면 그 단계는 완료되지 않았다. `ISM-*`, `COMP-*` 같은 코드는 L2 카탈로그의 항목 주소다.
>
> - **수행** — 누가 하는가. `연산`(Claude 수행) / `증거`(검색 또는 질문 — 생성 금지) / `판정`(사람). L0 §9
> - **QnA** — 이 단계에서 공백이 감지될 때 호출하는 질문 노드. `Q-S0-01` 형식. 정의는 `3_QNA_질문노드.md`
>
> 최초 작성 2026.09.30 · v0.5 개정 2026.09.30
>
> **우선순위 (L0 §1.1·§6.7)**: 판단이 부딪히면 사용자 경험과 조형 완성도가 방법론의 형식보다 앞선다. 더프롬의 1U·로고 형상·브랜드 컬러는 판단의 방법이지 클라이언트 결과물의 소재가 아니다(N7).

**되돌아가는 지점**: S4에서 실패한 게이트에 따라 돌아가는 단계가 다르다. §S4의 표 참조. 임의로 앞으로 밀지 않는다.

## S0 · 정의

무엇을 만드는지 한 문장으로 쓰지 못하면 여행을 시작하지 않는다.

| | |
|---|---|
| **입력** | 클라이언트 브리프, 기존 자산, 경쟁 환경 |
| **작업** | ① 컨셉을 **한 문장**으로 정의 ② 타겟·기기·맥락 기술 ③ 금지 사항 수집 ④ **G5 판정자 지정 — 1차(사내 비참여자 3명) 필수, 2차(외부 타겟) 가능하면** ⑤ 1U 적용 여부 판정 ⑥ **프로젝트 브랜드 확인** — 클라이언트(서비스)의 브랜드·컬러·톤. 더프롬 브랜드가 아니다(L0 §1.1) |
| **수행** | `연산` 초안(①~③⑤) · `판정` 판정자 지정(④)은 사람이 이름을 준다 |
| **QnA** | `Q-S0-01` 컨셉의 대상·상황 · `Q-S0-02` 타겟 · `Q-S0-03` 금지·제약 · `Q-S0-04` G5 판정자 · `Q-S0-05` 1U 적용 구분 · `Q-S0-06` 프로젝트 브랜드 (v0.4) |
| **산출물** | `S0_정의.md` — 컨셉 한 문장 / 타겟 / 매체·기기 / 금지 사항 / G5 판정자 1차·2차 이름 / 1U 적용 구분 / QnA 답과 명시한 가정 |
| **게이트** | 컨셉이 **한 문장**인가. 두 문장이면 아직 두 개의 프로젝트다. |

### 컨셉 한 문장의 형식

> `[대상]이 [상황]에서 [무엇]을 [어떻게] 느끼게 한다`

예:
- `도시에 사는 30대가 주말 아침 앱을 열 때 자연과 공존하는 일상을 서두르지 않는 속도로 느끼게 한다`
- `10~20대 스트리트 컬처 향유자가 이동 중 짧은 스크롤에서 스트리트 문화의 에너지를 거칠고 즉각적으로 느끼게 한다`

**서비스 이름·가칭은 S0에서 짓지 않는다.** 이름이 결과 해석을 미리 정하기 때문이다. 이름이 필요하면 C 게이트 이후에 짓는다.

**`[어떻게]`에 쓰는 것은 감정의 결까지다.** "서두르지 않는 속도로", "거칠고 즉각적으로"처럼 **어떻게 느끼는가**를 쓴다. 화면의 형상이나 결과 화면의 해석("나이테로", "쌓인 구조로")을 여기 쓰지 않는다 — 그것은 S2가 레이어에서 도출한다.

> v0.2까지의 예시 `자연과 공존하는 라이프 스타일` / `스트리트 문화의 에너지 넘치는 스타일`은 Knowhow Book 원문(Lv.2-2 톤앤매너 3단계)에서 온 것이다. 이들은 **톤앤매너 키워드 수준**이며 대상·상황·방식이 비어 있어 한 문장 형식에 못 미친다. 원문 예시는 무드 키워드로만 쓰고, 컨셉 한 문장은 위 형식으로 쓴다.

### G5 판정자를 여기서 정하는 이유

출구 판정(G5)은 2단으로 한다(L0 §6.3). 프로젝트 끝에 사람을 구하면 늦는다. **S0에서 이름을 적어둔다.**

| 단 | 판정자 | 지위 |
|---|---|---|
| 1차 | **해당 프로젝트에 참여하지 않는 사내 인원 3명 이상** | 필수 |
| 2차 | 타겟 조건에 해당하는 외부인 | 가능하면 |

1차의 조건은 '사내'가 아니라 **'비참여'**다. 참여자는 해석을 이미 알고 있어 자메뷰가 성립하지 않는다. S1~S3 리뷰에 들어온 사람은 1차 판정자가 될 수 없으므로, **S0에서 미리 빼둔다.**

### 1U 적용 여부를 여기서 판정하는 이유

1U는 불변 원칙이 아니라 기본값이다(L0 §2.2). 예외 상황(클라이언트 시스템·플랫폼 규격·인쇄·기존 자산 확장·단발 키비주얼)에 해당하면 **무엇을 1U로 삼을지를 S0에서 정한다.** S3에서 정하면 이미 조형이 진행된 뒤라 역산이 어렵다.

| 판정 | S3에서 하는 일 |
|---|---|
| 1U 적용 | 기본값 표(L0 §2.2.1)에서 시작 |
| 예외 — 클라이언트 시스템 | 클라이언트 단위를 1U로 삼고 그 안에서 파생 |
| 예외 — 플랫폼 규격 | 플랫폼 단위를 1U로 삼는다 |
| 예외 — 인쇄·환경 | mm 기준 1U를 새로 정한다 |
| 예외 — 기존 자산 확장 | 기존 값을 1U로 역산한다 |
| 예외 — 단발 키비주얼 | 스케일 생략, 비율(`RATIO-*`)만 특정 |

### 산출물 형식 ① — 여행기록

| 사조 ID | 선정 이유 | 가져올 것 (원리) | 두고 올 것 |
|---|---|---|---|
| `ISM-BAUHAUS` | 장식 근거를 요구하는 리뷰 문화가 필요 | 장식은 입증 대상이라는 판정 기준 | 원·삼각형·3원색 어휘 전체 |
| `ISM-KR` | 타겟이 국내 전 연령 | 색을 위치·관계의 코드로 쓰는 규칙 | 오방색 5색 팔레트, '한' 서사 |

### 산출물 형식 ② — 반대 대상 (`A4`)

L0 §4.2의 고정 형식을 그대로 쓴다: `[층위] · [지배 규범] → [어기는 지점] · [강도]` + 실례 2건 이상.

| 층위 | 지배 규범 | 어기는 지점 | 강도 | 실례 (2건 이상) |
|---|---|---|---|---|
| `CAT` | 국내 보험 브랜딩은 신뢰를 파랑·세리프·가족 사진으로 표기한다 | 신뢰를 여백과 단색 하나로만 표기 | 역전 | A사 2024 캠페인 / B사 브랜드 사이트 / C사 앱 온보딩 |
| `PLAT` | 미니앱 기본 카드는 모두 그림자와 라운드를 갖는다 | 그림자 제거, 경계를 선 하나로 | 이탈 | 플랫폼 기본 카드 / 상위 노출 미니앱 2건 |

**층위 6종**: `CAT` 카테고리 관습 · `COMP` 경쟁사 · `SELF` 우리 과거 · `PLAT` 플랫폼 기본 · `ISM` 사조 규범 · `EXP` 타겟의 기대
**강도 3종**: `이탈` · `역전` · `거부`

> **실례 2건을 못 채우면 그 반대 대상은 삭제한다.** 실례에는 출처(검색 주소 또는 `사용자 제공`)를 붙인다 — Claude는 실례를 생성하지 않는다(L0 §9.2). 실례 없는 반대는 상상 속의 적이고, 그 적을 공격한 조형은 S4에서 N1(차별을 위한 차별)로 판정된다.
>
> 실험적 조형을 쓰지 않는 프로젝트는 이 표에 `없음`이라고 적는다. **비워두는 것과 `없음`으로 적는 것은 다르다** — 빈 칸은 판단하지 않은 것이고, `없음`은 판단한 것이다.

### 왜 3~5개인가

2개 이하면 여행이 아니라 이식이다 — 한 사조의 스타일이 그대로 드러난다. 6개 이상이면 믹스가 아니라 죽이 된다 — 무엇 하나 근본이 남지 않는다.

### A3 판정 방법

`가져올 것` 칸에 적은 문장에서 **형태·색·서체 이름을 지운다.** 지운 뒤에도 문장이 성립하면 원리다. 문장이 사라지면 시각 인용이다.

- "굵은 검정 테두리와 하드 섀도" → 지우면 아무것도 안 남음 → **시각 인용, 반려**
- "무엇으로 만들어졌는지 숨기지 않는다" → 지울 것이 없음 → **원리, 통과**

## S2 · TUNNEL 진입 — 믹스와 레이어링

터널 안에서 하는 일은 두 가지다. **믹스**(사조를 조합해 조형 어휘를 만드는 일)와 **레이어링**(타겟·브랜드·UX를 겹쳐 범위를 좁히는 일).

**순서 (v0.5)**: 레이어 3종 → 패턴 재해석 + **효익 시각화** → **C 게이트(컨셉 판정)** → A/B 시안 → 크리틱 루프.

- v0.4는 컨셉과 메타포를 판정하지 않은 채 완성 시안까지 만들었다. 컨셉이 틀리면 그 비용이 전부 버려진다. v0.5는 **가장 싼 형태(문장·표·러프 1장)에서 사람이 먼저 판정**한다(L0 §6.8).
- v0.4의 결과는 컨셉 아이디어에 치우쳤다 — 메타포가 화면을 정했고, 사용자가 얻는 것이 **보이지** 않았다. v0.5는 메타포와 별도로 **효익 시각화**를 설계한다. 메타포는 시각화의 **톤**을 정하되 **형식**을 정하지 않는다.
- A/B의 정의를 바꿨다 — 아래 §A/B의 정의.

### 4축 조합 (T1)


### A/B의 정의 (T3) — v0.5 개정

A/B는 톤의 변주가 아니다. **방법론을 어디에 두느냐**의 두 갈래다.

| | **A · 시스템 주도안** | **B · 경험 주도안** |
|---|---|---|
| 방법론의 자리 | **형태를 결정한다** — 1U·그리드·규칙이 화면을 짓는다 | **컴포넌트 안에 녹는다** — 구조·포인트·디테일의 차이로 드러난다 |
| 컴포넌트 | 규칙에 맞춰 새로 만든다 | **사용을 제약하지 않는다** — 관습·플랫폼 컴포넌트를 자유롭게 쓴다 |
| 새로움이 나오는 곳 | 시스템의 일관성 | 컴포넌트의 구조를 바꾸는 한 수, 시선이 머무는 포인트, 디테일의 차이 |
| 위험 | **작위적 단조로움** — 모든 것을 1U로 짜서 생기는 단조로움. **명분만 있고 효익은 없는 개살구** | 흔한 앱과 구분되지 않음 (G1) |
| 역할 | **대조군** — 방법론을 전면화했을 때 무엇이 남는지 드러낸다 | **본안** |
| 범위 | 핵심 화면 1~2개, 크리틱 루프 1회 | 핵심 화면 전부, 크리틱 루프 2회 이상 |

**A를 만드는 이유.** A는 이기라고 만드는 안이 아니다. 방법론이 명분으로만 작동할 때 결과물이 어떻게 되는지를 **같은 컨셉 위에서** 보여준다. B가 A와 다르지 않다면 B도 개살구다.

**B에서 방법론이 녹아드는 곳** — 컴포넌트를 버리지 않고, 다음 셋 중 하나 이상을 바꾼다.

| 층 | 뜻 | 예 (성향 테스트의 선택지 버튼) |
|---|---|---|
| **구조** | 컴포넌트가 정보를 담는 방식 | 선택지가 "텍스트 한 줄"이 아니라 "내 답이 결과의 어디에 반영되는지"를 함께 담는다 |
| **포인트** | 시선이 머무는 단 한 곳 | 고른 순간 그 답이 쌓이는 자리 하나만 움직인다 |
| **디테일** | 상태·모션·타이포의 결 | 눌림 상태, 전환 곡선, 숫자의 서체 |

#### 명분·효익 표 — A와 B의 판정

시안의 설계 결정마다 **명분**(방법론의 근거)과 **효익**(사용자가 얻는 것)을 나란히 적는다.

| 결정 | 안 | 명분 | 효익 | 판정 |
|---|---|---|---|---|
| 예: 모든 카드 높이를 3U 배수로 고정 | A | 1U 파생 | — | **개살구** — 삭제 또는 효익을 찾는다 |
| 예: 결과 수치를 내 위치 점 하나로 | B | `VIZ-POS` · 레이어 ③ 동기 | 3초 안에 내 위치를 안다 | 유지 |

**효익 칸이 빈 결정은 개살구다.** B에서 개살구가 나오면 삭제한다. A에서 나오면 그대로 두고 기록한다 — 그것이 A의 역할이다. **선택은 효익 칸이 더 많이 차고 더 강한 안**으로 한다. 명분의 개수로 선택하지 않는다.

### 레이어 3종 (T2)

| 레이어 | 겹치는 방법 | 산출 |
|---|---|---|
| ① 타겟 | 연령·기기·숙련도·사용 맥락으로 조형의 범위를 정한다 — 가독성 하한, 정보 밀도, 톤의 폭 | 조형의 경계 조건 |
| ② 브랜드 특성 | **클라이언트(서비스)의 브랜드**에서 경쟁사와 갈리는 지점을 명시한다. 더프롬 브랜드로 채우지 않는다(N7). 브랜드가 없으면 서비스의 약속과 타겟에서 정한다 | 우리만의 색의 근거 |
| ③ 소비자 이용(UX) | 관성적 행태 목록화 — 무엇을 건드리면 안 되는가 · **핵심 순간의 동기와 감정** — 사용자가 이 화면에서 얻고 싶은 것 (v0.4) | **지킬 것 / 밀 것** 두 목록 + **화면별 동기** |

**③의 산출물이 가장 중요하다.** L0 §6.1의 "관성은 구조에서 지키고, 새로움은 해석에서 만든다"를 실제 목록으로 만드는 단계다.

| 지킬 것 (구조) | 밀 것 (해석) |
|---|---|
| 탐색 구조, 읽기 순서, 되돌아가기 | 크리에이티브 메타포 |
| 버튼이 버튼처럼 보이는 것 | 톤, 모션의 성격 |
| 접근성 — 대비·초점 순서·타깃 크기 | 타입의 표정, 컬러 해석 |

**화면별 동기 (v0.4)** — 핵심 화면마다 한 줄씩 적는다. 재해석의 `사용자가 얻는 것` 칸과 G4 ③이 이것을 기준으로 판정된다.

```
결과 화면 — 동기: 나를 설명하는 말을 얻고 싶다 / 감정: 들킨 듯한 놀라움, 인정받는 느낌
```

### 패턴 재해석 (T4) — v0.3 신설

**레이어 3종이 겹쳐진 뒤에** 한다. 메타포는 레이어에서 나오기 때문이다. L0 §6.1 "관성은 구조에서 지키고, 새로움은 해석에서 만든다"를 **화면 단위의 설계**로 내리는 단계이며, S4의 G4·G6이 이 산출물로 판정된다.

핵심 화면마다 네 동작을 순서대로 한다.

| 순서 | 동작 | 기록 | 참조 |
|---|---|---|---|
| ① | **기성 UI 패턴 명시** | `PAT-*` ID + 지킬 가독성(누구나 기대하는 작동) | L2 PART D |
| ② | **통상적 해석 기록** | L0 §4.2 반대 대상 표기 형식 + 실례 2건 이상 | L0 §4.2 · §9.2 |
| ③ | **크리에이티브 메타포 도출** | 레이어 ①타겟 ②브랜드 ③UX에서 — 어느 레이어에서 나왔는지 적는다. 더프롬의 철학·형상은 출처가 될 수 없다(N7) | L0 §5.2 |
| ④ | **메타포로 패턴 재해석** | **비주얼**과 **작동** 두 칸을 모두 설계하고, **사용자가 얻는 것**을 적는다 — 화면별 동기와 연결되어야 한다 | `MOTION-*` `STATE-*` · L0 §6.4 ③ |

**메타포는 프로젝트에 하나다.** 화면마다 메타포가 다르면 그것은 G2의 "우리만의 색"이 아니라 화면별 아이디어다. 화면별로 달라지는 것은 메타포가 아니라 **재해석**이다.

**②의 실례는 생성하지 않는다.** L2 PART D의 `통상적 해석` 칸은 **가설**이다. 그 가설을 반대 대상으로 쓰려면 실제 실례 2건을 검색하거나 사용자에게 받아 붙여야 한다(L0 §9.2). 못 채우면 그 화면의 반대 대상은 `없음`이고, 재해석은 가독성 유지 범위의 **이탈** 강도에 그친다.

**④는 세 칸이 모두 차야 한다.** 비주얼만 채우면 스킨이고, 작동만 채우면 표면이 비어 있다 — 둘 다 S4 G6에서 실패한다. `사용자가 얻는 것`이 비면 다름은 만든 사람의 것이다 — G4 ③에서 실패한다.

**좋은 메타포는 좋은 조형을 허락한다.** 메타포를 화면에 옮겼을 때 위계가 흐려지거나 정보가 도표처럼 읽힌다면, 조형을 억지로 맞추지 말고 메타포를 의심한다(L0 §6.7).

#### 산출물 형식 — 메타포 + 화면별 재해석 표

```
메타포: [한 문장]
출처 레이어: ① / ② / ③ 중 — 근거 한 줄
```

| 화면 | 패턴 (`PAT-*`) | 지킬 가독성 | 통상적 해석 (반대 대상 형식) | 실례 (2건·출처) | 재해석 — 비주얼 | 재해석 — 작동 | 사용자가 얻는 것 |
|---|---|---|---|---|---|---|---|
| 예: 결과 | `PAT-RESULT` | 결과가 무엇인지 첫 화면에서 읽힌다, 공유·다시하기로 나갈 수 있다 | `CAT` · 성향 테스트 결과는 유형명+일러스트 카드 한 장으로 끝난다 → … · 이탈 | (검색 결과 주소) / (사용자 제공) | … | … | … (화면별 동기와 연결) |

### 효익 시각화 (T4) — v0.5 신설

재해석이 **무엇을 다르게 볼까**라면, 효익 시각화는 **사용자가 무엇을 볼 수 있게 되는가**다. 메타포가 화면의 형식까지 정하면 결과는 컨셉 아이디어에 머문다. 그래서 둘을 나눈다.

> **메타포는 시각화의 톤을 정한다. 시각화의 형식은 사용자의 과업이 정한다.**

핵심 화면마다 다음을 적는다.

| 칸 | 질문 | 예 (결과 화면) |
|---|---|---|
| **과업** | 사용자가 이 화면에서 해야 하는 일 — 이해 · 비교 · 결정 · 공유 · 기록 중 | 내가 어떤 사람인지 **이해**하고, 친구에게 **공유**한다 |
| **보이게 할 것** | 과업을 빠르게 하려면 무엇이 보여야 하는가 | 4축 위에서의 내 위치, 같은 나이대와의 차이 |
| **시각화 형식** | `VIZ-*` 중에서 — 시각화가 필요 없으면 `없음 — 문장으로 충분` | `VIZ-POS` + `VIZ-CMP` |
| **효익 지표** | 관찰 가능한 문장으로 — "~초 안에 ~를 안다", "~없이 ~를 할 수 있다" | 설명 없이 3초 안에 가장 강한 축을 말할 수 있다 |
| **메타포의 톤** | 메타포가 이 시각화에 주는 것 — 형식이 아니라 결 | "인물 기사" → 도표가 아니라 기사 속 인포그래픽의 결 |

**시각화에는 여지를 둔다.** 메타포에 맞추느라 과업에 맞지 않는 형식을 고르지 않는다. 반대로, 효익 지표가 문장만으로 달성된다면 시각화를 억지로 넣지 않는다 — `없음`도 판단이다.

**러프 1장.** 핵심 화면(보통 주인공 화면) 하나를 **와이어 수준**으로 만든다 — 톤·색·디테일 없이, 무엇이 어디에 얼마나 크게 보이는지만. 이것이 C 게이트의 판정 재료다. 완성 시안을 만들기 전에 방향이 맞는지를 가장 싸게 본다.

### C 게이트 · 컨셉 판정 — v0.5 신설

A/B 시안을 만들기 **전에** 사람이 판정한다(L0 §6.8). 이 게이트를 통과하기 전에는 완성 시안·시스템·실체화에 비용을 쓰지 않는다.

**판정 재료** — `kit/C_컨셉판정.md` 한 장:

| 항목 | 내용 |
|---|---|
| 컨셉 한 문장 | S0 |
| 메타포 후보 2~3개 | 각각 출처 레이어 + 권장안 표시 |
| 화면별 재해석 한 줄 | 지킬 것 / 바꿀 것 / 사용자가 얻는 것 |
| 효익 시각화 | 과업 · 형식 · 효익 지표 |
| 러프 1장 | 주인공 화면 와이어 (`proto/rough.html` 또는 캡처) |
| 다음 단계 비용 | A/B 시안 → S5까지 무엇을 만들게 되는지 |

**판정** — go(권장 메타포로 진행) / 수정(다른 메타포·효익 재설계 → S2 레이어부터) / 중단.

**묻는 것**: 아름다운가가 아니라 **맞는 방향인가, 사용자에게 무엇을 주는가, 이 비용을 쓸 가치가 있는가**.

**무인 실행**: 사용자가 "끝까지 진행"을 명시하지 않았다면 **여기서 멈추고** 판정 키트를 넘긴다 — 비용 원칙이 우선이다. 명시했다면 권장안으로 진행하고 `C 게이트 — 무인, 권장안으로 진행`이라고 적는다.

### 컬러 역할 배분

60-30-10 법칙. 주색 60% / 보조색 30% / 강조색 10%.

- **프로젝트(클라이언트) 브랜드 컬러**에서 주색·보조색을 고른다. 브랜드 컬러가 없으면 레이어 ①②에서 새로 정하고 근거를 적는다 (v0.4)
- **더프롬 팔레트(L0 §3)는 더프롬 자사 산출물에만 쓴다.** 클라이언트 작업의 공백을 더프롬 컬러로 채우지 않는다(N7)
- 강조색은 소량만. 많이 쓰면 강조 효과가 사라진다

### 시안과 크리틱 루프 (T5) — v0.4 신설

시안은 한 번에 만들고 끝내지 않는다. **B(본안)와 final은 최소 2회, A(대조군)는 1회** 돈다. B의 두 번째 루프가 끝난 뒤 A와 B의 명분·효익 표가 선택을 분명히 가르면, A는 추가 루프 없이 멈춘다.

```
화면 캡처 → G7 ①~⑦ + G3 자기 비평 → 가장 약한 3곳 수정 → 다시 캡처
```

| 회차 기록 (시안마다) | 형식 |
|---|---|
| 본 것 | 가장 약한 3곳 — 각각 G7 항목 번호로 (예: `①위계 — 결과 화면 1순위가 유형명인지 도면인지 불분명`) |
| 고친 것 | 3곳 각각 무엇을 바꿨는가 |
| 남은 것 | 다음 회차로 넘기는 것 |

비평은 **디자이너의 눈**으로 한다 — "규칙을 지켰는가"가 아니라 "이 화면이 좋은가, 무엇이 먼저 보이고 무엇이 거슬리는가". 1U·정렬 규칙 위반은 여기서 찾지 않는다(그것은 S3 U1·U2).

### U1의 판정 기준 — 8px이 아니라 파생 근거

1U는 값이 아니라 방법이다(L0 §2.2). 따라서 U1은 "8px 배수인가"를 묻지 않는다. **"이 치수는 어떤 단위에서 파생되었는가"**를 묻는다.

| 상황 | U1 판정 |
|---|---|
| 간격이 12px인데 1U를 12px로 정했고 표가 그렇게 쓰여 있다 | **통과** |
| 간격이 8px 배수지만 1U를 정한 문서가 없다 | **실패** — 우연히 맞은 것과 파생된 것은 다르다 |
| 클라이언트 시스템의 4px 그리드를 1U로 삼고 그 안에서 파생했다 | **통과** |
| 어떤 값은 8의 배수, 어떤 값은 5의 배수 | **실패** — 파생 출발점이 둘이다 |

### U2 예외 처리

좌측 정렬이 아닌 것, 직각이 아닌 것, 1U보다 가까이 붙은 것은 **전부 근거를 적는다.** 규칙이 조형을 해치면 규칙을 바꾸고 근거를 적는다 — 조형을 규칙에 맞추지 않는다(L0 §6.7). 단 컴포넌트 **내부** 간격(아이콘-라벨 등)의 0.5U는 예외가 아니라 규칙이다(L0 §2.2.2). 근거 없으면 규칙으로 되돌린다(N2 — 근거를 설명할 수 없는 조형 금지).

```
예외: 히어로 타이틀 중앙 정렬
근거: COMP-SYM 대칭 구도 — 브랜드 선언 화면으로 정돈·완성도 인상이 목적. 
      이하 모든 섹션은 좌측 정렬 유지.
```

### 열 수를 역산한다는 것

12열은 관행이지 원리가 아니다. 스위스 스타일이 남긴 것은 숫자가 아니라 **"열 수는 콘텐츠의 분할 요구에서 역산한다"**는 방법이다(→ `ISM-SWISS` 그리드 기여). 3분할이 필요 없는 제품에 12열을 쓰면 6열이 놀고 있는 것이다.

## 단계를 건너뛸 수 있는 경우

전체 파이프라인은 신규 브랜드·신규 제품 기준이다. 다음은 축약 가능하다.

| 상황 | 축약 |
|---|---|
| 기존 브랜드의 신규 화면 | S1·S2 생략, 기존 `S1`·`S2` 문서 참조. S3부터 시작. 단 신규 화면이 **핵심 경험**이면 S2 패턴 재해석은 생략하지 않는다(L0 §7.3-5) |
| 단일 키비주얼 | S3의 그리드·타입 스케일 생략, 비율(`RATIO-*`)·구도만 결정 (L0 §2.2.3 예외) |
| 캠페인 변주 | S1 생략, S2에서 무드만 재조정 |

**어떤 경우에도 S4(게이트)는 생략하지 않는다.** 판정 없이 나가는 산출물은 없다.
