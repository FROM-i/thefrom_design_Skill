### 1. THE FROM 디자인 철학 — 판단의 기준

**THE FROM, 나로부터.** 모든 Creative는 결국 나로부터 시작되어 발현된다. 레퍼런스에서 시작하지 않고, 트렌드에서 시작하지 않고, **판단하는 사람**에게서 시작한다는 선언입니다. 그래서 이 스킬은 모든 단계에 "누가, 무엇을 근거로 그렇게 판단했는가"를 남깁니다.

| 철학 | 뜻 | 스킬에서는 |
|---|---|---|
| **1U** | 로고의 가장 작은 정사각형 한 변. 이 하나에서 로고의 모든 치수가 나온다 | 모든 간격·글자 크기·반경을 **한 단위에서 파생**한다. 1U는 값이 아니라 방법이고, 화면에서는 **보이지 않는 뼈대**다 |
| **노랑** | 아이부터 노년까지, 전 세대 | 팔레트가 아니라 **태도**. 항상 쓰는 색이 아니다 |
| **자메뷰** | 데자뷰의 반대 — 익숙한 것을 처음 보는 것처럼 느끼는 것 | 사용자에게 **낯선 구조를 주지 않는다.** 익숙한 구조를 새로 보이게 하는 **해석**을 준다 |

이 셋을 한 문장으로 묶은 것이 스킬의 원칙입니다.

> **관성은 구조에서 지키고, 새로움은 해석에서 만든다.**

철학은 **판단의 방법**이지 결과물의 소재가 아닙니다. 클라이언트 결과물에 1U 모양이나 더프롬 컬러를 새기지 않습니다.

### 2. 디자인 방법론 — 에어플레인 이펙트 / 터널 이펙트

#### ✈ 에어플레인 이펙트 — 여행

다양한 디자인 철학과 사조를 **경계 없이 여행하고 섞어**, **근본 있는 하이브리드**를 만든다. 여행은 자유롭지만 결과물은 근본이 있어야 하므로 세 가지 규칙을 지킵니다.

| 규칙 | 뜻 | 예 |
|---|---|---|
| **원리만 가져온다** | 모양을 가져오면 코스튬이 된다 | 바우하우스에서 "장식은 이유를 입증해야 한다"는 가져오고, 원·삼각형·3원색은 두고 온다 |
| **두고 올 것도 적는다** | 사조마다 계승하면 실패하는 부분이 있다 | 절대주의의 비기능성을 가져오면 "무엇을 눌러야 할지 모르는 화면"이 된다 |
| **무엇에 반대하는지 먼저 적는다** | 표적 없는 파격은 소음이다. 실례 2건이 없으면 반대하지 않는다 | "성향 테스트 결과는 다 유형명+캐릭터 한 장이다" → 실제 서비스 2곳 이상에서 확인한 뒤에만 |

#### ◐ 터널 이펙트 — 레이어링

여행에서 얻은 것을 들고 **어두운 터널에 진입**한다. 진입할 때는 정답이 없어서 어둡다. 세 겹의 레이어를 겹칠수록 정답의 범위가 좁아지고, **밝은 출구**가 보인다.

| 레이어 | 질문 | 얻는 것 |
|---|---|---|
| ① 타겟 | 누가, 어떤 순간에 보는가 | 조형의 경계 — 글자 크기의 하한, 정보의 밀도 |
| ② 브랜드 | 무엇이 이 클라이언트만의 것인가 | 우리만의 색의 근거 |
| ③ 사용 습관 | 사람들은 실제로 어떻게 쓰는가, 그 순간 무엇을 원하는가 | **지킬 것**(관성)과 **바꿀 것**(해석)의 목록 |

**출구**는 일곱 가지 조건이 동시에 성립할 때만 열립니다 — 기성을 따라 하지 않았다 · 우리만의 색이 있다 · 쓰던 방식을 해치지 않는다 · 익숙한 패턴에 새 해석과 효익이 있다 · 처음 본 사람이 "어, 이거" 한다 · 작동과 비주얼 모두에 컨셉이 있다 · 포트폴리오에 올릴 완성도다.

### 3. 방법론을 위해 검토한 사조 — 관성과 예술성

사조는 이 스킬의 첫 번째 재료입니다. 사조에는 두 가지가 들어 있습니다.

- **관성** — 지금 우리가 "당연하다"고 느끼는 디자인 규칙이 어디서 왔는가. 12열 그리드는 스위스 스타일에서, "기본값을 믿어라"는 브루탈리즘에서, 여백을 의미로 읽는 감각은 일본 미학에서 왔습니다. 관성의 출처를 알아야 **무엇을 지킬지** 압니다.
- **예술성** — 각 시대가 지배적인 규범을 정확히 겨눠 깨뜨린 원리. 멤피스는 모더니즘을, 해체주의는 "당연한 위계"를 겨눴습니다. 깨뜨린 원리를 알아야 **어디서 새로워질지** 압니다.

16개 사조를 검토했고, 각각 **가져올 것(원리)**과 **두고 올 것(모양만 빌리면 실패하는 것)**을 나눠 기록했습니다.

| 사조 | 시기 | 가져올 것 — 원리 | 두고 올 것 |
|---|---|---|---|
| 미술공예운동 | 1861– | 장식은 구조에서 나온다 — 그림자·보더는 상태의 신호로만 | 텍스처·손글씨 폰트로 만든 '수공예 룩' |
| 아르누보 | 1883– | 선의 가속·감속 → 모션 이징의 원리 | 본문에 쓰는 곡선 레터링 |
| 미래주의 | 1909– | 글자는 의미를 만드는 재료다 | 가독성·접근성을 무너뜨리는 타입 |
| 아르데코 | 1910s– | 장식을 기하학으로 규율한다 → 스케일의 근거 | 금색 그라데이션의 '개츠비 템플릿' |
| 절대주의 | 1915– | 환원은 검증 절차 — 빼도 기능하는가 | 누를 곳이 사라진 비기능성 |
| 구성주의 | 1915– | 빼도 무너지지 않는 요소는 지운다 | 목적 없는 사선·적흑백 포스터 룩 |
| 다다 | 1916– | 고르고 충돌시키는 것도 저작이다 | 표적 없는 어지러운 콜라주 |
| 데 스틸 | 1917– | 적은 어휘, 무한한 관계 → 디자인 토큰 | 적·황·청 + 검정 격자 (몬드리안 인용) |
| 바우하우스 | 1919– | 장식은 입증 대상 · 재생산 가능한 부품 | 원·삼각형·3원색 |
| 스위스 스타일 | 1950s– | 그리드는 결정 비용을 줄이는 도구 | 그리드를 감옥으로 만들기 |
| 브루탈리즘 | 1950s– | 무엇으로 만들었는지 숨기지 않는다 | 굵은 테두리·형광·하드 섀도 스타일 |
| 포스트모던·멤피스 | 1966– | 성격은 기능과 동등한 설계 대상 | 반대할 대상 없이 빌린 형태 |
| 해체주의 | 1967– | "이 위계는 누가 정했는가"를 묻는다 | 어긋남·중첩·사선의 시각 레시피 |
| 펑크·DIY | 1976– | 도구를 열면 참여가 늘어난다 | 대기업 캠페인에 입힌 '펑크 룩' |
| 일본 미학 | 14C– | 완결을 유보해 보는 사람의 참여를 요구한다 | 크라프트지·와비사비 클리셰 |
| 한국 전통 미학 | 고전 | 변수를 결과로 받아들이는 설계 · 색은 질서의 코드 | '비애의 미' 같은 식민기 프레임, 무맥락 오방색 |

전체 기록은 [`method/2_CATALOG_기성의_관점.md`](method/2_CATALOG_기성의_관점.md) PART A.

### 4. 더프롬 Knowhow Book — 스킬과 테크닉

두 번째 재료는 더프롬이 직접 정리한 조형 교재 **Knowhow Book** 3권입니다. 사조가 "왜 이렇게 하는가"라면, 노하우북은 "**무엇으로, 어떻게 잘 만드는가**"입니다. 원문 표현을 유지한 채 항목마다 ID를 붙여 스킬이 찾아 쓸 수 있게 했습니다.

| 권 | 담긴 것 | 스킬에서 쓰이는 곳 |
|---|---|---|
| **Lv.1 Principles of Design** (37p) | 디자인 12원칙 — 균형 · 비율 · 강조 · 대비 · 리듬 · 정렬 · 위계 · 여백 · 움직임 · 반복 · 다양성 · 통일. 그 기준은 **시각적 무게감**(색상·크기·형태·위치·여백) | 완성도 판정 — 1순위 정보가 3초 안에 읽히는가, 강조점은 하나인가 |
| **Lv.2-1 Detail Expression in Design** (66p) | 디테일 3층 — 앵글 5 · 뷰 14 · 빛과 그림자 24 · 질감 12. "디테일은 요소를 많이 넣는 것이 아니라 어떻게 보여주고, 드러내고, 느끼게 하는가" | 마지막 실체화 단계의 디테일 |
| **Lv.2-2 Visual System** (112p) | 톤앤매너 = 컬러 × 무드 × 비주얼 스타일 × 타이포. 컬러 19 · 무드 5 · 비주얼 스타일 4 · 타이포 6 · 구도 23 · 그리드 10 · 레이아웃 9 · 비주얼 요소 12 | 시안의 톤앤매너 조합, 구도·그리드·레이아웃 결정 |

여기에 스킬을 만들며 UI 패턴 12 · 모션 7 · 상태 5 · 시각화 8을 더해, 사조와 합쳐 **219개 항목**을 참조합니다 — [`method/2_CATALOG_기성의_관점.md`](method/2_CATALOG_기성의_관점.md) PART B·D.

### 5. 두 재료가 만나는 곳 — 익숙함의 새로움, 터널의 출구

| | 사조 | Knowhow Book |
|---|---|---|
| 담긴 것 | **관성과 예술성** | **스킬과 테크닉** |
| 알려주는 것 | 무엇이 익숙한지, 어디서 새로워질 수 있는지 | 그것을 어떻게 잘 만드는지 |
| 방법론에서 | 에어플레인 — 원리를 모은다 | 터널 — 겹친 레이어를 조형으로 옮긴다 |
| 없으면 | 예쁘지만 어디서 본 것 같은 화면 | 새롭지만 완성도가 낮은 화면 |

두 재료를 함께 써야 **자메뷰** — 쓰던 대로 쓰는데 처음 보는 것 같은 화면 — 가 나옵니다.

**예 — 성향 테스트의 진행 바.**
누구나 아는 진행 바(관성)는 그대로 둡니다. 다만 막대 하나를 **네 영역 × 두 칸**으로 나눠, 답을 고를 때마다 "방금 답이 어느 영역에 반영됐는지"가 보이게 합니다(해석). 사용자는 평소처럼 답을 넘기지만, 처음으로 **내 답이 결과가 되어 가는 과정**을 봅니다. 이것이 이 스킬이 말하는 터널의 출구입니다.

### 6. 스킬로 옮기며 정한 것

- **판단은 사람이, 연산은 AI가.** AI는 초안·재해석·시안·검증을 하고 근거를 남깁니다. 경쟁 사례·레퍼런스는 **지어내지 않고** 찾거나 묻습니다. 방향(컨셉)과 완성도의 최종 판정은 사람이 합니다.
- **브리프가 먼저.** 무엇을 · 누구에게 · 핵심 순간이 비면 아무것도 만들지 않습니다.
- **비싼 단계는 판정 뒤에.** 러프 한 장으로 방향을 먼저 확인받고(C 게이트), 그 뒤에 완성 시안을 만듭니다.
- **A/B는 늘 두 갈래.** A는 1U 규칙이 형태를 정하는 안(대조군), B는 컴포넌트는 자유롭게 쓰고 방법론을 구조·포인트·디테일에 녹이는 안. 결정마다 "명분"과 "사용자가 얻는 것"을 나란히 적고, 얻는 것이 없는 결정은 버립니다.

### 7. 어떻게 다듬어졌나

앱인토스 성향 분석 미니앱을 같은 브리프로 세 번 만들어 보며 고쳤습니다.

| 회차 | 드러난 문제 | 고친 것 |
|---|---|---|
| 1회차 | 1U를 화면 모양으로 상징화하고, 조형·UX를 놓침 | 1U는 보이지 않는 뼈대 · 조형 완성도 판정 신설 · "사용자가 얻는 것" 필수 |
| 2회차 | 컨셉 아이디어에 치우쳐 효익이 보이지 않음 · 판정 없이 끝까지 만들어 비용 위험 | 효익 시각화 · 러프 한 장으로 먼저 판정(C 게이트) · A/B 재정의 |
| 3회차 | 브리프 없이도 되는 것처럼 보임 | 브리프 게이트 · 브리프 편집기 |

방법론 원본의 개정 이력은 [`method/`](method/) 각 문서 끝에 있습니다.

## 설치 — 직원용

### Claude 데스크톱 앱 (Cowork)
1. 왼쪽 **Customize → Plugins**
2. **Add marketplace** → `FROM-i/thefrom_design_Skill` 입력
3. 목록에 뜬 **thefrom-ux** → **Install**
4. 마켓플레이스에서 **Sync automatically** 켜기 — 이후 수정본이 자동 반영됩니다

한 번 설치하면 계정에 저장되어 채팅·Claude Code에서도 같은 스킬을 씁니다.

### Claude Code
```
/plugin marketplace add FROM-i/thefrom_design_Skill
/plugin install thefrom-ux@thefrom
```
비공개 저장소라면 먼저 `gh auth login` → `gh auth setup-git`으로 GitHub 인증을 저장해 두세요.
자동 업데이트는 `/plugin` → Marketplaces → thefrom → **Enable auto-update**.

### ChatGPT · Gemini 등 다른 AI에서
[`portable/README.md`](portable/README.md) — 지침 한 장(`portable/instructions.md`)과 지식 파일 8개(`portable/knowledge/`)로 맞춤 GPT·Gem을 만드는 방법.

### 쓰는 법 — 브리프가 먼저입니다
**"더프롬처럼 만들어줘"로는 시작되지 않습니다.** 이 스킬은 감각을 흉내 내지 않고 판단을 계산하며, 판단의 재료는 브리프입니다.

1. **브리프 편집기로 씁니다** — [`tools/brief-editor.html`](tools/brief-editor.html)을 브라우저로 여세요(더블클릭, 설치 없음).
   - ★ 필수 6항목을 칸마다 채우면 오른쪽에서 **브리프 게이트 판정**(통과 / 질문부터 / 멈춤)과 **모호한 표현 경고**가 바로 보입니다.
   - 쓰는 동안 브라우저에 자동 저장되고, **.md 저장**으로 `브리프_프로젝트명_날짜.md`를 내려받습니다. **불러오기**로 다시 열어 고칠 수 있습니다.
   - 저장한 브리프는 [`briefs/`](briefs/)에 커밋해 팀이 공유합니다.
   - 편집기 없이 쓰려면 양식 [`templates/brief.md`](templates/brief.md)를 복사해 채워도 됩니다.
2. 브리프 .md를 첨부하고 "더프롬 방식으로 진행해줘"라고 요청합니다.
3. 부족한 항목이 있으면 스킬이 **질문부터** 합니다. ★1·★2·★3이 비면 아무것도 만들지 않습니다 — 정상 동작입니다.
4. 기본은 **C 게이트(컨셉 판정)에서 멈춥니다.** 방향을 확인한 뒤 "끝까지 진행"을 요청하세요.

## 방법론을 고칠 때 — 관리자용

1. `method/`의 문서를 고친다. L0는 합의를 거치고 개정 이력을 남긴다.
2. `python3 scripts/build_references.py` 로 스킬 참조본을 다시 만든다.
3. `plugins/thefrom-ux/.claude-plugin/plugin.json`의 `version`을 올린다. **버전을 올리지 않으면 직원들에게 반영되지 않는다.**
4. 커밋·푸시. `ci/check-references.yml`을 `.github/workflows/`로 옮겨 두면 GitHub Actions가 `references/`와 `method/`가 어긋났는지 검사한다. (워크플로 파일은 `workflow` 권한이 있는 계정으로 한 번만 올리면 된다.)

SKILL.md를 고칠 때도 3번(버전)을 잊지 않는다.
